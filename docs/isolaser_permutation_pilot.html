isoLASER has no false discovery rate (FDR) control, so we estimated one by permutation: shuffle which allele each read carries, score the shuffled data the same way as the real data, and count how many associations pass by chance. This pilot covers one chromosome and one timepoint, chr9 at 6 hours, where HNRNPK is located.

Result in brief. The screen on the genome-wide page has an estimated FDR of about 43.1% here: roughly 4 in 10 of its hits would be expected by chance. Adding a requirement on each association’s own permutation p-value brings the estimate down to 4–8%, and an independent set of permutations confirms it. HNRNPK passes every cutoff we tested.

Why a permutation test

isoLASER labels an association cis when its score exceeds the 99th percentile of a null distribution that ships with the software. That is a cutoff for each test separately, not control of the FDR across many tests. isoLASER’s p-values can’t be used for FDR control either: associations with no allele difference all get p between 0.42 and 0.55, and the p-values sometimes contradict the cis label. A permutation test builds the null distribution from our own data instead.

How the permutation works

The question is: if a variant had no effect on splicing, how many associations would still pass the screen?

In each shuffle
Shuffled For each donor, gene and isoLASER phasing group, the haplotype labels (which parental chromosome a read came from) are randomly reassigned among the reads. A read whose label changes is given the other allele at every variant in that phasing group. The few reads without a haplotype label have their alleles shuffled at each variant.
Kept fixed Each read’s splicing status (whether its transcript includes or skips each exonic part), each donor’s read depth, and which donors count as heterozygous for each association.
Broken Only the link between allele and splicing.
Scored Exactly as the real data: the heterozygous donors’ 2×2 tables (allele × part included or excluded) are pooled and scored with isoLASER’s own functions, then the same filters are applied.

Two details matter:

  • Shuffling haplotype labels, rather than each variant’s alleles separately, keeps variants on the same haplotype consistent with each other, and keeps the exonic parts that share reads linked.
  • Some shuffled tables end up with fewer than 10 reads on one allele and get no score; this happens for about 5.5% of shuffled values. They count as not passing.

Starting from isoLASER’s own read assignments

The shuffle has to use the alleles isoLASER itself assigned to each read, because alleles read directly from the BAM files don’t reproduce its counts exactly. isoLASER doesn’t save them, so we reran its per-donor step for chr9 at 6 hours with a copy that records them. Before any permutation, we checked:

Check Result
The recording copy gives the same output as an unmodified copy run with the same random seed identical, all 4 donors

isoLASER has two random steps, downsampling reads for very deep genes and the starting point of phasing, so the rerun differs from the original run in a few other associations, mostly in TPM2. The rerun is used for both the real and the shuffled data.

What we ran

All runs use chr9 at 6 hours, with 2,788 tested associations (variant × exonic part with a scorable heterozygous-donor table).

Batch Permutations Random seed Used for Run time (24 cores)
Selection 1,000 1 choosing stricter cutoffs 4 minutes
Validation 1,000 2 re-checking the chosen cutoffs 4 minutes
HNRNPK focus 100,000 3 a precise p-value for HNRNPK’s associations only 16 minutes

For a given cutoff, the estimated FDR is the average number of associations passing in the shuffled datasets, divided by the number passing in the real data. We calculate it separately for associations (variant × exonic part at this timepoint) and for genes, since one gene can have several associations.

How to read the columns: Real data is the number passing without shuffling. Shuffled average is the mean count across 1,000 shuffles in the selection batch. Shuffled, 95% range shows where the middle 95% of those 1,000 counts fell; it is not a confidence interval for the FDR. Estimated FDR divides the shuffled average by the real count. Estimated FDR, validation repeats that calculation using a separate 1,000-shuffle batch with a different random seed, without changing the cutoff. Similar estimates in the two batches are a check that the finding is not peculiar to the first random set of shuffles. These are estimated null-to-observed ratios, not a count of known false rows.

Stricter cutoffs

Before running these batches, we fixed a grid of 32 stricter cutoffs. Each adds to the website screen a choice of:

  • |ΔPSI| ≥ 0.10, 0.15, 0.20 or 0.30;
  • at least 1 or 2 heterozygous donors;
  • a maximum row p-value of 0.01, 0.003 or 0.001, or none.

The row p-value is our own addition: it compares an association’s real score with its own shuffled scores in the selection batch. p ≤ 0.001 means no shuffle scored as high as the real data. It is what lowers the estimate most:

Estimated FDR is the mean number of passing associations across the selection shuffles divided by the real passing count. Validation is the same ratio calculated from the second, independent batch of 1,000 shuffles; the row p-value limit is kept fixed when doing this check.
