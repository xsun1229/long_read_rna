What this run is

A test of the full per-donor → joint isoLASER pipeline on chr21, using the 0 hr library. The point was to establish that the chain runs correctly and to measure the event yield at per-donor depth before committing to a genome-wide run — not to produce biological results.

Why per donor at all: isoLASER’s phasing assumes one diploid genome (weighted k-means, K = 2). Run on the pooled BAM it splits donors rather than haplotypes — we demonstrated that directly, so the pooled cis/trans calls were uninterpretable. Splitting first makes each donor’s haplotype table valid; isolaser_joint then pools those tables across donors.

Scripts: 3.isolaser_per_donor/ — 1.split_bam_by_donor.sbatch, 2.run_isolaser_per_donor.sbatch (SLURM array), 3.run_isolaser_joint.sbatch. All three completed.

Verdict

The pipeline works. Split → per donor → combine_vcf (GATK) → isolaser_joint runs clean, and the joint step behaves as designed.

The yield at this depth does not support biology. 7 genes on chr21, with per-donor filtered counts of 0–18, is a plumbing result.

Scaling up

chr21 is ~1.5% of the genome. Genome-wide gives each donor 6.2–9.3 M reads instead of 62–101 k — roughly 90× more — which should lift per-donor yields into a usable range.

With all three timepoints now available, the joint analysis could also run over 12 samples (4 donors × 3 timepoints) rather than 4. Alternatively the timepoints can be pooled per donor to maximise depth, since haplotypes do not change with stimulation.

Blocker for the genome-wide run

We only have chr21.fa. Going genome-wide needs:

  1. the full GRCh38 FASTA (refdata-gex-GRCh38-2024-A, ~11 GB), indexed with .fai and .dict
  2. the GTF normalisation, transcriptome FASTA and exonic-parts DB rebuilt for all contigs

Notes for reproducing

Several non-obvious things are baked into the scripts:

  • Do not use samtools fastq. 20.5% of reads have QUAL='*', and mixed QUAL/no-QUAL input makes it truncate silently — 629,035 reads in, 14,255 out, no error. The scripts convert with awk and assert the read count matches.
  • isolaser_extract_exon_parts does not create its -o directory. mkdir -p first or it dies in pandas.
  • Keep the #chrom header on line 1 of mi_summary.tab before bgzip — isolaser_filter uses pd.read_csv(..., escapechar='#') and fails with KeyError: 'label' if it has been sorted into the body.
  • PyVCF3 is required but undeclared — setup.cfg has #PyVCF commented out, so isolaser_joint dies on import vcf until it is installed.
  • Pass -n — isoLASER spawns 64 processes by default, which the login-node watchdog kills. Run under SLURM.
  • || true after sort | head — set -o pipefail otherwise turns SIGPIPE from head into a job failure after the analysis has succeeded.
  • Results are not bit-reproducible; phasing uses k-means with random initialisation, so marginal events move between runs.
