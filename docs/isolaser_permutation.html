Adjusted p-value for each association

The test: for one variant–part association, compare its observed isoLASER association score (AMI) with its own scores from the shuffled reads. A larger AMI means a stronger allele–splicing link. If \(B\) permutations are run,

\[ p_{\mathrm{perm}} = \frac{1 + \#\{\text{permuted AMI} \geq \text{observed AMI}\}}{B+1}. \]

For the two full batches together, \(B=2{,}000\). A permutation with an undefined score is counted as at least as extreme, making the reported p-value conservative. With no permutation more extreme, the smallest available p-value is \(1/2{,}001 \approx 0.00050\), not zero.

We apply the BH multiple-testing adjustment to these p-values across all 2,788 chr9, 6-hour rows with a defined observed score. This yields one q-value per association. Smaller q-values offer stronger evidence after accounting for the number tested. Here 0 rows have q < 0.05, and 19 have q < 0.10. Among the 20 original-screen rows, 4 have q < 0.10. These are adjustments within chr9 at 6 hours; including the other chromosomes and timepoints will increase the number of tests.

The question the permutation asks

isoLASER links a variant’s allele to whether a long read includes an exonic part. For each variant–part pair, a 2 × 2 table counts reads with the reference or alternate allele and with the part included or excluded. A strong link can be called cis, but screening many such tables can still produce apparent links by chance. We ask: how many would pass the same screen if we broke the allele–splicing link while keeping the observed reads and their splicing patterns?

Here is a made-up example. H1 carries REF and H2 carries ALT for this variant. The column “part included?” stays attached to each read during permutation.

Read Part included? Original haplotype / allele Shuffled haplotype / allele
A Yes H1 / REF H2 / ALT
B Yes H1 / REF H1 / REF
C No H2 / ALT H1 / REF
D No H2 / ALT H2 / ALT

Originally, both inclusion reads carry REF and both exclusion reads carry ALT. After one shuffle, each splicing outcome has one of each. Repeating the shuffle shows how often a link at least as strong as the observed one appears by chance.

The actual shuffle works within each donor × gene × phasing group. It redistributes haplotype labels among reads in that group. When a read changes label, its alleles at the linked variants are flipped together; its exonic-part statuses do not change. For reads without a usable haplotype label, alleles are shuffled within that variant. The same shuffled allele is used for that read across every part tested for the variant. Variant coverage and the donor set selected from the observed data stay fixed. A shuffled table can have an undefined score if too few reads remain on one allele; the cutoff analysis treats it as failing the screen.

This preserves connections among parts and linked variants better than filling each 2 × 2 table with independent random numbers. Its interpretation still rests on reads being exchangeable within the groups where labels are shuffled; it does not remove mapping bias or alignment artifacts.

What we ran and checked

This first run covers chr9, 6 hours, four donors (CD_21, CD_31, CD_36, CD_48). It was chosen because the HNRNPK example is on chr9. The original screen required at least 30 informative reads from each contributing donor for a variant–part pair, an observed allele fraction of 0.25–0.75 for that donor, a cis label, |ΔPSI| ≥ 0.10, a part at least 10 bp long, and no other tested variant within 30 bp. A “passing row” means one variant × exonic part × timepoint association; several rows can belong to the same gene.

isoLASER did not save its variant-specific allele assignment for each read. We therefore reran its Nanopore-model analysis once with a recording copy that saved those assignments. The rerun, rather than the earlier unseeded output, is the observed dataset used below. No alignment or variant calling is repeated for each shuffle.

Before permuting, all four donors passed checks that the recording copy and a control copy produce identical variant, splicing-table and haplotype outputs. Every recorded variant–part read table reproduced isoLASER’s counts. Pooling and rescoring the unshuffled records then matched all 5,578 / 5,578 joint rows from the rerun. This is a check that the permutation starts from the same statistics as the observed analysis.

We ran 1,000 selection permutations, then 1,000 independent validation permutations with a different random seed. A fixed grid of 32 cutoffs varies |ΔPSI|, the minimum number of heterozygous donors (one or two), and each row’s empirical permutation p-value. The selection batch chooses a cutoff; the validation batch estimates its null count again. A separate 100,000 permutation focus run tests the selected HNRNPK association. The first, older 1,000-permutation experiment is excluded from these results.

How to read the screen-level result

For any cutoff, both real and shuffled datasets must pass the same rules. The reported estimate is

\[ \text{estimated null/observed ratio} = \frac{\text{mean number passing in a permuted dataset}} {\text{number passing in the observed dataset}}. \]

For example, at the original cutoff, 20 rows pass in the real data and 8.519 pass in a validation shuffle on average: 8.519 / 20 = 42.6%. This ratio is an estimated permutation FDR under this shuffle scheme, not a guarantee that this exact fraction of the observed rows is false.

HNRNPK: a focused check

The highlighted HNRNPK association links chr9:83980154:C>T to chr9:83980118-83980152:-, with 2 qualifying donors and 326 pooled informative reads. Its observed |ΔPSI| is 0.214. None of the 100,000 focused shuffles produced an association score at least as large, giving \((0+1)/(100{,}000+1)\) = 0.00001. This is an unadjusted, candidate-specific p-value for this association, selected after the initial screen. It is evidence that this particular link is stronger than expected under the shuffle; it does not test a change from 0 to 6 hours or by itself control for the many associations screened.

Across all 2,788 rows with a defined observed score, the two full batches give zero BH q-values below 0.05 and 4 original-screen rows below 0.10. The HNRNPK row’s BH q-value from those full batches is 0.073. The 100,000 focused shuffles improve resolution for HNRNPK’s own p-value; they are not incorporated into that adjustment across the chr9, 6-hour tested rows.

Does this result make sense, and what remains?

Yes, with limits. The original screen retains more rows than the null average (20 versus 8.5), while a cutoff requiring stronger evidence retains fewer rows and has a much smaller null/observed ratio. The independent validation batch gives a similar answer to the selection batch (4.5% versus 3.8% for the selected 5% row cutoff). The near-1% cis rate among shuffled defined scores is also reassuring.

The null can miss technical artifacts that cause a real read-level allele–splicing link, including allele-dependent mapping or variants close to splice boundaries. Even the stringent four-row result merits read-alignment inspection and independent support. Most importantly, this pilot covers only chr9 at 6 hours. Repeating it across chromosomes and timepoints is needed before reporting a genome-wide error rate or testing a stimulation interaction. A change in which timepoints pass a cutoff is not, by itself, a test of that interaction.
